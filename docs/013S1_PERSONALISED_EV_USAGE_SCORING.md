# 013S1: Personalised EV Usage Prediction and Scoring Recommendation

## Purpose

This feature extends the existing personalised EV insights flow with an explainable EV readiness score and recommendation. It uses the responses already collected by the web form and stored through the Node API.

The result includes:

- an EV readiness score from 0 to 100;
- `Full EV Recommended`, `Hybrid Recommended`, or `EV Optional`;
- estimated annual distance, fuel cost, EV charging cost, savings, and CO₂ reduction;
- a personalised explanation;
- the component scores and calculation assumptions; and
- the existing K-Prototypes driver segment for backwards compatibility.

## Request flow

```text
React questionnaire
  -> POST /api/personalised-ev-insights
  -> MongoDB response record
  -> POST /personalisedEVInsights/predict
  -> K-Prototypes driver cluster + 013S1 suitability score
  -> persisted result
  -> GET /api/personalised-ev-insights/latest
  -> readiness summary and comparison charts
```

## Score

The readiness score is an additive, bounded decision-support score:

| Component | Maximum points | Basis |
|---|---:|---|
| Driving demand | 20 | Weekly kilometres |
| Financial benefit | 25 | Estimated annual savings |
| Charging practicality | 25 | Home access and preferred charging location |
| Solar access | 10 | Household solar availability |
| Environmental priority | 10 | User-selected environmental priority |
| Budget readiness | 10 | Self-reported vehicle budget |
| Long-trip constraint | −5 | Regular road trips without home charging |

Categories use the task thresholds:

- 70–100: `Full EV Recommended`;
- 45–69: `Hybrid Recommended`; and
- below 45: `EV Optional`.

The implementation lives in [`scoring.py`](../server/python-services/personalisedEVInsights/scoring.py). Constants are named and the API returns the assumptions used, so the result is auditable and can be reproduced in Power BI.

## Financial and environmental estimates

Annual kilometres are weekly kilometres multiplied by 52. Annual fuel cost is monthly fuel spending multiplied by 12. EV charging cost uses a transparent per-kilometre estimate selected from the user's charging profile:

- solar: $0.02/km;
- home: $0.04/km;
- work: $0.05/km; and
- public or no preference: $0.07/km.

Tailpipe emissions use the submitted fuel efficiency with 2.31 kg CO₂/L for petrol or 2.68 kg CO₂/L for diesel. Estimated EV electricity use is 0.18 kWh/km, with 0.65 kg CO₂/kWh for grid charging or 0.05 kg CO₂/kWh for the solar profile. Negative savings and reductions are floored at zero. Switching benefits are not reported for respondents who already own an EV or do not own a car.

These figures are indicative estimates, not quotes. Electricity tariffs, fuel prices, vehicle efficiency, lifecycle emissions, and grid intensity vary by vehicle, place, and time.

## Interpretation and limitations

This is a first-stage EV suitability prediction and recommendation system using behavioural, financial, environmental, and charging-related indicators. It must not be described as a validated prediction of real-world EV adoption.

The supplied project overview describes supervised model comparison against recommendation categories generated by scoring logic. No labelled source dataset or executable notebook was supplied with this task, so this implementation does not claim the reported 92% accuracy or weighted F1 performance. Training a classifier to reproduce a deterministic score would measure imitation of that score, not real adoption accuracy.

A future validated ML version requires:

1. consented outcome labels such as later EV purchase or stated adoption intent;
2. a documented data extract and privacy process;
3. leakage-safe train/test evaluation and class-balance reporting;
4. calibration, subgroup fairness, and stability analysis;
5. a versioned model artifact and feature contract; and
6. monitoring after deployment.
